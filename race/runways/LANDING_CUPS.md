# Landing cups

Groupings of `race/runways/*.json` for landing-mode nights. Docs only, like `race/courses/CUPS.md`:
no schema field, nothing reads this file. Every runway below was generated by
`race/tools/add_runway.py <ICAO> <END>` from OurAirports (2026-09-24 download) — threshold,
elevation, true heading, length and width are OurAirports' numbers, with the threshold moved down
the runway by any displaced threshold (and `length_m` shortened to match). The touchdown zone is the
default rule (10–30 % of length, clamped 60–450 m). Each file's `notes` records its provenance and
anything derived.

**None of these has been flown in GeoFS yet.** GeoFS's own runway placement can differ from
OurAirports by tens of metres; fly each one once and compare the touchdown `along_m`/`cross_m` the
server reports before trusting a board.

## Caveats

- **Scoring assumes a flat runway.** Lukla (~12 %) and Courchevel (~18 %) are steeply sloped; the
  server's along-track/rollout maths is flat-earth, so rollout penalties there are optimistic and a
  touchdown's `thr_alt_m` comparison (if ever added) would be wrong along the slope.
- **Courchevel direction:** the famous landing is uphill. OurAirports puts the 04 end at 6583 ft and
  the 22 end at 6371 ft, so the uphill landing is runway **22** — that's what `lflj-22` is. If GeoFS
  or the AIP disagrees, add `lflj-04` with `add_runway.py LFLJ 04 --derive-missing-end` (OurAirports
  has no coordinates for the 04 end, so they'd be derived from the 22 end + length) rather than
  editing this one.
- **Saba** (`tncs-12`): OurAirports has no end elevations (airport elevation used) and no true heading
  (computed from the two end coordinates); it also lists a 170 ft displaced threshold, leaving 348 m.
- Direction choices for the Mountain/Home runways are the commonly-filmed ones, not a claim about the
  active runway on any given day.
- Already on the board from the launch set (not part of these cups): `sea-tac-16c`, `friday-harbor-16`,
  `sisters-eagle-air-34`.
